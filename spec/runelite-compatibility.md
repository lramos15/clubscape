# RuneLite status

Status: **ClubScape compatibility not implemented or verified**.

The upstream versions and host smoke evidence in
[`docs/machines/sparky.md`](../docs/machines/sparky.md) do not establish a
ClubScape scene bridge, state/event model, live connection or plugin support.

The first compatibility experiment must be separately bounded before execution:
pin runtime/plugin builds, available tools/resources, the launch/scene/event
interfaces to exercise and a stop condition. Require a live ClubScape scene
with penguin and at least one real generic overlay/tracker. An API-shaped mock
or upstream launch is not Tier 1.

No experiment or desktop deferral is approved as completed in this checkpoint.
Browser delivery may proceed independently. Any eventual deferral requires the
Section 12 evidence review and owner approval; no native-client substitution
is authorized.

## Bounded M1 companion experiment

Task `M1-RUNELITE-FEASIBILITY` reserves one worker within the shared25-agent
ceiling. It does not gate or expand the mandatory browser/headless journey.
Use the already selected official RuneLite1.12.38 runtime/plugins and injected
client revision240 with the pinned cache2695 source, not a new freshness search.
Record exact library/build hashes before execution. The named first generic
plugin target is XP Tracker; an actually working generic tile/ground overlay
may supplement it but must be identified separately.

Sparky's verified ARM64 JDK11/17, Xvfb, existing native RuneLite libraries and
loopback ClubScape/PostgreSQL test tooling are available. Recheck executable
locations before use. Do not change system graphics/sandbox settings, create or
log into an external game account, reuse private source-account configuration,
or purchase infrastructure. Isolate Java's `user.home` explicitly.

Evaluate no more than two materially distinct adapter architectures and three
live integration attempts. Each attempt must identify its hypothesis and
failure diagnostics. Stop when the real-runtime demonstration works, or the
bounded experiments are exhausted; no repeated blind retries or nested agents.
Preserve runnable code/evidence and report missing prerequisites rather than
treating a time/resource limit as proof of impossibility.

A successful demonstration must connect to the real authoritative ClubScape
service, render the source slice scene and penguin player, reflect live state
changes, and run a named genuine RuneLite generic plugin over real server
events. Synthetic source-state fixtures, fake XP callbacks, an API-shaped
shim, reference PNGs and the earlier upstream EULA launch cannot satisfy it.
The experiment must not move authoritative rules into Java or weaken the
browser contracts. Report a support-tier claim only for the complete tested
tuple; otherwise record the precise missing launch/scene/state/event/plugin
links and the cost/risk of a viable next approach. A recommendation to defer
remains pending owner approval, never silently accepted.
