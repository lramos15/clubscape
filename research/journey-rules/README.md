# M1 starter behavior contracts

**Source-contract task, not an implemented or accepted game.** These records
are owned by `m1-journey-rules`; they change no server, protocol, shared spec,
asset, presentation target, or approval record.

The JSON is generated by `author_contracts.py`; edit that authoring source and
regenerate those six contracts. **Fixtures are separately authored** and never
generated from the contracts or game. They must stay independent oracles.

### Integration boundary

Use kind-first semantic IDs, not guessed numeric varps/item/object IDs.
`*_ref`/`*_refs` point to declared records. Runtime content extraction must bind
the precise source variant, geometry and interface. Do not use guide markers
as certified object origins or substitute a demonstration square.

Guards inspect authoritative post-event state, then transition effects commit.
Gathering/cooking/smithing/combat events mean the real shared operation happened;
the graph does not perform it or grant its XP again. UI opens must respect
progressive unlocks. Effect operations, durable reward ledgers and predicates
are specified in `vocabulary.json`; `state.inventory.*` counts are projections,
not client assertions. A valid graph edge is necessary, **not sufficient**, to
authorize an item mutation.

Earlier unlocked activities remain available at reachable source workshops for
loss recovery, subject to explicit tutorial restrictions. No `advance tutorial`
event exists. Completing the tutorial quest does not itself remove island
caps or teleport the player.

## Findings that change implementation

* Current **Learning the Ropes** is tracked and awards **1 QP on the valid
  chicken Wind Strike**, before departure. A chicken kill is not required;
  accepting a splash is labeled an inference.
* The transcript explicitly allows **burnt shrimp** to move on. Real failure
  outcomes must exist; do not guarantee cooking success to pass the journey.
* The bank visibly contains **25 coins at first opening**, before poll
  inspection. Opening it again must not reseed coins.
* Vannaka's one-slot sword/bow grants and missing-item replacements are not
  all-or-nothing generic quest rewards. Initial arrows are **50**, departure
  arrows **25**; initial runes are **five pairs**, departure runes differ.
* Tin is prompted first, but symmetric ore messages support either real mining
  order. Bronze smelting is **6.2 XP (62 tenths)**, not 6.25; dagger smithing
  is 12.5. Bronze pickaxe cadence is **8 ticks**, not one guaranteed ore/tick.
* Skilling's published success function includes `+1` and rounding: level-1
  copper is **101/256**, shrimp fishing **49/256**. Firemaking parameters are
  explicitly crowdsourced/unverified and are not promoted to verified facts.
* Ordinary shortbow uses 4-tick accurate/longrange, 3-tick rapid, 7/9-tile
  range and equipped arrows; ordinary arrow loss is 20%. Bread/shrimp eating
  adds a 3-tick attack/eating delay.
* The first **item-losing** death triggers Death's Office. Fees, timer and
  kept-items topics must all be covered; the portal remains locked and the
  grave timer paused until then. An empty-inventory death need not trigger it.
* Cook's Assistant permits **pre-collected ingredients and partial deliveries**.
  Its quest guards must not require self-gathering or gathering after start.
  M1's journey evidence must nevertheless actually acquire ingredients
  legitimately. Rewards are **1 QP + 300 Cooking XP + range access**, no coins.

## Version choice and remaining precision work

This behavior profile is the pinned **post-July-2026 normal F2P journey**.
Cache 2695 is historical, not a prerequisite. The independent runtime worker
chooses the usable gamepack/cache and records its actual identity. If that
client predates these behaviors, keep the mismatch explicit; do not silently
replace 24 skills, Learning the Ropes, post-2025 energy or July-2026 grave
layout behavior with older mechanics.

The current detailed transcript wins over the older guide's absent
music/emote/friends/ignore lessons. This is a documented variant choice, not
permission to hide controls. Exact optional-control visibility remains a
presentation/source-binding question. The run demonstration is preserved;
whether walking past it is source-permitted is not established by a refusal
transcript, so its strict graph gate is labeled an inference.

**Critical for exact fidelity:**

1. **Departure reconciliation**: source supports standard provisions and loss
   of gathered items, but not a complete inventory/equipment/bank dump after
   deposit/drop/withdrawal. The explicitly provisional policy normalizes all
   tutorial containers, puts 18 item kinds in inventory, and restores 25 bank
   coins. Do not call this an observed result. Capture that matrix and replace
   only this policy.
2. **Selected goblin loot variant/supplement**: the numeric primary table sums
   to 128 before three newly listed “Common” energy-potion rows with no
   probabilities. Bind the actual level-2 spawn/table and potion condition.
   Guaranteed bones, NPC stats and published primary weights are usable now;
   bones-only or guaranteed coins is not complete loot fidelity.
3. **External binding**: actual tiles/floors/collision/cameras, numeric UI/
   progress bindings where needed, projectile launch/impact timing and a
   pinned death-value provider remain the other worker/Director's inputs.
   `null` means unverified, never zero/no delay/no reward.

Other localized precision choices are enumerated in `decisions.json`: initial
container/security defaults, tutorial XP boundary rounding, missing-tool
fallbacks, asymmetrically depleted rune top-ups, first-bread guarantee, dough
container byproducts, run/fire/tree timing, negative combat rolls, HP XP thirds,
shop overstock conflict, death ties and mill ownership/overflow.
Tutorial-bone XP, Home Teleport cooldown start and kill-credit ties have
explicit local inference labels. These do not block independently verified
mechanics; none is owner approval of a material adaptation.

## Reproduce and validate

From this worktree root, using existing Python 3 and only the standard library:

```sh
python3 research/journey-rules/author_contracts.py
python3 research/journey-rules/validate.py --self-test

# Optional network reproduction of the exact pinned public revisions:
python3 research/journey-rules/fetch_sources.py
python3 research/journey-rules/validate.py --snapshots --self-test --report
```

Normal fetching uses the committed revision IDs, not current pages. `--discover`
is only for deliberate new research, never routine reproduction. Raw wiki
prose/API caches stay in the owned ignored `.local/` and were cleaned after
validation; hashes describe exact UTF-8 wikitext without an added newline.
The wiki contributor/history and copyright links are preserved in the source
manifest. Prose snapshots are not bundled as dialogue/assets, and no Jagex
asset license is inferred from them.

Validation checked IDs/references, three graphs' forward and reverse
reachability, reward claim-site/key uniqueness, all six partial-delivery
orders, fixture/rule XP consistency and all source hashes. It executed
38 arithmetic, 29 guard and 23 graph oracle vectors. Separately, 53 outcome,
six checkpoint and four whole-journey records are **requirements**, not server
runs. Six deliberately corrupted in-memory contracts were rejected.

Chrome/Edge gameplay, persistence under actual server failures, rendering,
audio, source fidelity, performance, RuneLite and owner presentation approval
still require their separate M1 acceptance evidence.
