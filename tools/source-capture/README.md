# Original-runtime reference capture fixtures

This executes the **original pinned injected runtime**, not a ClubScape renderer,
cache-library model viewer, screenshot pasted into a candidate, or hand-painted
approximation. The JAR is unchanged. The host supplies an isolated, explicit
offline rendering state and original cache data to its real methods.

**No source account was created or logged in; no terms were accepted. These
fixtures are reference preparation, not an approved reference pack or evidence
of a legitimate source/ClubScape player journey.**

## Run and verify

Read `AGENTS.md` and `docs/machines/sparky.md` before building. Use Python 3.12
and JDK 17. No GPU, browser, X server, global configuration changes, Python
packages or audio device are required.

```bash
python3 tools/source-capture/capture.py
python3 tools/source-capture/capture.py --verify-only
python3 -m unittest discover -s tools/source-capture -p 'test_*.py' -q
```

The default source is the prior extraction worker's
`.worktrees/m1-runtime-inputs/.local/current-source`, reused read-only or
hardlinked into **this** worktree's ignored `.local/source-capture/`. Original
cache/JAR sizes and SHA-256 values are verified before reuse and cache hashes
again afterward. Only the matching `client-1.12.38.jar` resource dependency was
newly downloaded; its bootstrap hash is locked in `dependencies.json`.
`/runelite/index` is required by the real archive API. Its 33 overlays concern
clientscripts (index 12); these fixtures do not invoke those scripts.

For another checkout with the integrated importer inputs already prepared:

```bash
python3 tools/source-capture/capture.py --source .local/current-source
```

If inputs are missing, first run the existing importer's `fetch` and `prepare`
commands as documented under `tools/cache-import/`. The capture tool fails
nonzero for absent/corrupt inputs rather than changing source identity or using
substitutes. It never reads personal `~/.runelite`.

Optional flags: `--profile models|scenes|title|all`, `--output PATH`,
`--seed INTEGER`, and `--java-home PATH`. Output must remain in this worktree.
`--verify-only` validates committed captures without Java or a cache download.

All executions use a fresh isolated Java `user.home`, headless AWT and
worktree-local scratch paths. The original `tg` framebuffer provider wraps the
actual pixel array; ImageIO disk caching is disabled. The JVM explicitly exits
after closing the cache, including on errors, so the original secure-random
executor cannot keep a fixture process alive.

For deterministic preparation, the process-local
`--add-opens=java.base/java.lang=ALL-UNNAMED` permits **only the host's seeding
of this JVM's `Math.random` generator**. This is not a browser sandbox/profile
change, global JVM setting, source-JAR modification, or authorization bypass.
The renderer's random algorithms remain original; the fixture seed is recorded.
Source `SecureRandom` and any external account/authentication system are not used
or seeded by this operation. Seed 0 produced byte-identical PNGs on two runs.

`assets/reference/osrs240/captures.json` is the canonical capture inventory;
`provenance.json` records exact artifacts, source files, JVM flags and validation.
The default **93 original-renderer PNGs** comprise:

* four textured/recolored ordinary-tree views at 1920×1080;
* all 16 goblin idle + 16 walk frames and all 14 penguin idle + 8 walk frames,
  each generated by original NPC assembly, lighting, scaling and animation;
* 24 original generated 36×32 item icons, including the bronze pickaxe, copper,

* one explicitly labeled native font/sprite test sheet;
* five original scene-viewport fixtures: Lumbridge castle/plaza, river/bridge,
  Tutorial starting house, survival coast, and the windmill route;
* five original title-painter states: initial loading, welcome, empty login,
  invalid-login UI and unaccepted terms.

The title painter states are **controlled states**, not observed authentication
responses or an observed transition past terms. No handler was called. The
registration website has not been captured. Title composition is the original
painter's native centered 765-wide area inside a 1920×1080 canvas, not a redesigned
full-screen composition. Source terms/links and source logos are retained.

The world images are **viewport-only**. They do not contain a complete
Resizable-Classic HUD or authoritative NPC/player/ground-item layers. Those
server-backed layers were not fabricated. No camera is labeled a verified
spawn/arrival camera; locations and elevations come from original map data, while
camera positions are explicitly chosen fixture controls.

## Why these are original rendering

The host calls the same native implementation classes and live method paths used
by the pinned runtime:

* `vp.az -> va.bw` loads real protocol-7 JS5 indexes; actual containers feed native
  `va/vp.loadData`. CRC and low-16-bit disk versions are checked against indexes.
* `ec` provides native texture loading/sampling. Both its rasterizer binding and
  the scene loader's shared texture-provider binding are installed.
* `ModelData`/`Model` APIs use the original model parser, lighting and projection.
  Tree object 1277's source recolor 3470→5029 is retained.
* `pl.ag` performs original NPC model assembly, source scaling, and animation
  transforms. Goblin 3028 uses 6181/6180; penguin candidate 2063 uses 5668/5666
  and its source scale 75/128. **This does not approve it as the player avatar.**
* `Client.createItemSprite` performs the actual native inventory-icon projection,
  lighting, outline, shadow and quantity text.
* `zv` measures and draws native font glyphs; `SpritePixels.drawAt` draws native
  sprites. The pinned cache library only decodes the glyph masks supplied to the
  original font constructor—it does not replace font rendering.
* `rl4.fn` builds original terrain, object placement, floor color blending,
  shadowing and scene geometry. `ez.dh` rasterizes that actual scene; this is not
  a replacement world viewer. Culling and occlusion remain enabled.
* `hs.ai` paints the real title/login states; original JPEG decoding, background
  mirroring, indexed sprites and graphics-defaults flame palettes are used.

The member bindings are version-specific. Dead obfuscator aliases are not
interchangeable with the live methods: one unused index-decoder alias caused an
allocation failure during investigation. The working path is explicitly pinned.
The native client instance and current-thread/archive/context bindings are
supplied by the host; the normal game loop and JS5 network pump are never run.

`MutedAnimationAudio` intercepts **only** animation sound-event callbacks in the
graphics fixture. Original animation stepping and all rendering remain native.
Audio synthesis/playback is intentionally left to the separate audio task.

## Calibration and checks

Per-image metadata includes source IDs, PNG/pixel hashes, dimensions, nonblank
pixel/color counts, geometry bounds/topology, source animation/frame identity,
camera parameters and native readbacks.

Important coordinate distinction: the legacy `Model.drawFrustum` arguments use
2048 units per turn; this runtime's `up` scene-camera controls use **16384** units
per turn. Scene capture pitch 2048 is 45°, not the legacy 256 value.
`Client.getCameraX/Y/Z` readbacks use horizontal X/Y and vertical Z; `ez.dh`
arguments are X/height/horizontal-Y. These orders are recorded explicitly.

Scene camera height is computed from the **native source focal-ground height**,
not from an assumed zero-height floor. Tutorial Island's starting-house ground
is -1360 in this source. Skipping this datum initially placed a camera below
the terrain; those failed attempts are not published as references.

The scene fixture uses native locked-camera controls, source-derived viewport
zoom from `rl.cu`, draw distance 25, brightness 0.8, stock 128-pixel textures and
an explicit far clip of 32768 source units. The far clip and camera are
**declared fixture choices**, not claimed observations of live-session defaults.
The original visibility initialization runs once for the configured draw
distance and retains its normal lifecycle.

All-zero fixture varps are sized from original varbit definitions. They are not
claimed to represent a fresh character or any tutorial/quest stage. Dynamic
object choices therefore need comparison against actual authorized account
state. Scenery is not relocated; source region IDs and absolute camera tiles
are in the manifest.

Validation checks input/output hashes, PNG CRCs and actual scanlines, original
geometry/index bounds, source-preserving transforms, all animation-frame indices,
nonconstant animated vertex hashes, native camera readbacks, source elevation,
nonempty scenery and exact PNG readback versus native pixels. HotSpot exception
logging detects **swallowed native rendering errors**: nonblank pixels alone
previously hid a missing native framebuffer dependency, and are not sufficient
for acceptance.
